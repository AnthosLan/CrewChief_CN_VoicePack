⚠ 装之前先备份

全程不要直接修改原来的语音包目录。下面第 1 步会让你复制一份出来再改， 这样任何时候都能一键退回英文。

① 先选一种装法

只影响语音那部分。界面文案和语音指令跟这个选择无关，两种装法都能装。

多数人选这个

用法 A · 原版 CrewChief

工程师和 spotter 全部说中文。装的时候要删掉 numbers 文件夹， 所以圈速、差距里的数字仍是英文（「你的圈速是 one twenty-three point four」）。

已经能拿到 5170 条中文播报。不需要任何编程环境。

需要开发环境

用法 B · 自己编译的 CrewChief

全部装上，数字也说中文（「一分二十三秒四」），问「现在几点」也按中文语序播报 （「上午八点零五分」）。

多出来的是 numbers 那 138 条 + 中文钟点语序。需要 Windows + Visual Studio，见 自己编译。

② 装语音

  1. 找到语音包目录 %LOCALAPPDATA%\CrewChiefV4\Sounds

    把上面这行直接粘到文件资源管理器地址栏，回车即可打开。

  2. 整个复制一份到别处 D:\CrewChief_zh\Sounds

    路径可以自己定。这一步是你的退路，不要跳过。

  3. 把压缩包里的 voice 合并进复制出来的目录，覆盖同名文件。

    用法 A 必读

    合并之前先把压缩包里的 voice\numbers\ 整个文件夹删掉。 不删会导致圈速中英混播，念成「四十五 point six」—— 原因。用法 B 全部合并，不用删。
  4. 告诉 CrewChief 去哪里读
    打开属性页（界面上叫 Properties 或「设置项」），在搜索框里搜：
    英文界面Override default Sound Pack location
    中文界面语音包
    填入第 2 步的路径。

    ⚠ 已经装了界面中文化的话，搜英文原文是搜不到的

    搜索框只匹配显示出来的标签和帮助文本，不匹配属性的内部名 （UserInterface/PropertyFilter.cs:141），而这一项装了中文界面后显示为 「覆盖默认语音包位置」。搜「语音包」两个字最省事。

    这一项没有游戏过滤，默认一定可见。搜不到就先确认「类别过滤」不是停在别的分类上。

  5. 用法 B 追加：新建或编辑 D:\CrewChief_zh\Sounds\sound_pack_language.txt 内容就写一行 zh。

    用法 A 不要建这个文件，保持原样。

  6. 用法 A 追加：防止下载按钮把英文包盖回来
    编辑 D:\CrewChief_zh\Sounds\sound_pack_version_info.txt 把里面的版本号改成一个很大的值，比如 9999。

    原因见关于自动更新。用法 B 不需要这一步。

  7. 确认两个语音下拉框都是默认值
    工程师语音和 spotter 语音。这一步很关键，原因见下。
  8. 重启 CrewChiefOverride 这个设置需要重启才生效。

⚠ 装完一点声音都没有？先看这一节

这是实测中最耗时间的一个问题，而且几乎不是语音包的问题。典型症状：

  • 一点声音都没有，连启动时的无线电测试也没有
  • 日志里明明有 Sound: ... 这类行，说明程序认为自己在播
  • 一行报错都没有

先自证语音包是好的

看 DebugLogs 里的日志，找这一行： Finished preparing sounds cache, found NNNNN driver names and NNNN sound sets 只要 sound sets 这个数和装中文包之前一致（本包的文件夹名全部来自英文包， 一个新的都不加），语音包就是装对的，问题在播放链路的下游。

为什么别的程序有声音，只有 CrewChief 没有

别的程序都用 Windows 默认输出设备。CrewChief 不是——它自己存了一个设备 GUID。 所以「浏览器放视频有声音」完全不能说明 CrewChief 也有声音，两者走的是不同的设备。

日志里这一行就是它当前用的设备：

Sound: Detected saved message audio output device: XXXXX

如果那个名字不是你正在用的耳机／音箱（比如它写着主板的「扬声器 (Realtek)」，而你其实听显示器 或 USB 耳机），那就是它了。

三步排查，从省事到彻底

  1. 先关掉 nAudio——一分钟，而且能直接定性
    属性页搜 nAudio，取消勾选「Use nAudio for playback」，保存，重启。

    关掉之后 CrewChief 改用 System.Media.SoundPlayer，直接播到 Windows 默认设备，完全绕开它自己那套设备选择。

    有声音了确定是设备选错 → 做第 2 步改对，然后把 nAudio 开回来
    还是没有继续第 3 步

    ⚠ 别长期关着 nAudio

    关掉之后 spotter 失去打断工程师的能力（InterruptCurrentlyPlayingSound 只对 nAudio 生效），贴身缠斗时「左边有车」会排在工程师长句后面，晚两秒到就没意义了。
  2. 在主界面上换设备（不在属性页里）
    「Messages playback device」下拉框换成你真正在听的那个设备，下面的 「Background playback device」一起换。
  3. 把配置炸掉
    退出 CrewChief，删掉整个文件夹 %LOCALAPPDATA%\Britton_IT_Ltd

    ⚠ 会清掉所有设置，包括第 4 步填的 Override 路径，重开后要重填。

⚠ 卸载重装 CrewChief 解决不了这个问题

因为设置根本不在程序目录里。日志开头自己写着 UserConfigFolder: C:\Users\<你>\AppData\Local\Britton_IT_Ltd。 卸载程序不会碰这个文件夹，你的设备选择、音量、全部属性都原样躺在里面，重装之后一字不差地读回来。 上游源码对这个文件夹的注释就一句话（DataFiles.cs:50）：唯一想对它做的事就是绝望时把它炸掉。
顺便排除两个便宜的可能

Windows 音量合成器里 CrewChiefV4 这一条被静音或拉到 0。这是每应用独立的， 别的程序有声音不代表它没被静音。

换播放接口：属性页搜 nAudio Output Interface，把 WaveOut 换成 WASAPI（需要重启）。 上游自己的说明是「WaveOut 兼容性更好，WASAPI 更直接」，但有些声卡上 WaveOut 会静默失败。

③ 装界面中文化（可选，原版程序就能用）

语音包只管「听到的」，界面上的按钮、菜单、设置项名称还是英文。想一起中文化就装这个—— 一个纯文本文件，不需要重新编译。

  1. 把压缩包里的 ui_text_zh.txt 复制到 %LOCALAPPDATA%\CrewChiefV4\

    注意是直接放在 CrewChiefV4\ 下面，不要建子文件夹。

  2. 改名为 ui_text.txt
  3. 重启 CrewChief

共 1305 条，覆盖主界面、菜单栏、全部设置项和帮助文本。没翻译到的条目自动回落英文，不会出现空白。

⚠ 装完还是英文？先看用户目录下有没有 ui_text 文件夹

覆盖层的两个位置是二选一，不是合并（Configuration.cs:212）：

%LOCALAPPDATA%\CrewChiefV4\ui_text\en.txt存在就只读它
%LOCALAPPDATA%\CrewChiefV4\ui_text.txt上面那个不存在时才读这个

所以只要用户目录下有 ui_text 文件夹且里面有 en.txt，我们这份 ui_text.txt 会被完全忽略。把那个文件夹挪走即可。

注意区分：安装目录下的 ui_text\en.txt（比如 D:\Games\Britton IT Ltd\CrewChiefV4\ui_text\en.txt）是上游自带的英文底本， 本来就该在那儿，不会挡我们，别删它。挡路的只有用户目录下的那个。

另外装失败是完全静默的——LoadAndMerge 里的异常被 catch(Exception){} 吞掉了， 不会有任何提示，界面就是保持英文。只能靠肉眼判断。

编码不用管：程序用 new StreamReader(路径) 读，默认 UTF-8 且会探测 BOM， 带不带 BOM 都能正确显示中文。

为什么放用户目录而不是安装目录？

CrewChief 按这个顺序合并界面文案，后面的覆盖前面的：

安装目录\ui_text\en.txt → 安装目录\ui_text\<语言>.txt → %LOCALAPPDATA%\CrewChiefV4\ui_text.txt

最后一个优先级最高，而且在用户目录下，程序更新不会覆盖它。 放安装目录里的话每次更新都得重装一遍。

⚠ 有一类设置项的值仍是全大写英文，那是正常的

像 UI_STARTUP_AND_PATHS、RESTART_REQUIRED 这些是程序内部标识符， 不是给人看的文字。本包故意不译——译了会让设置项从分组里消失、或者游戏过滤失效。 这不是漏做。

④ 装中文语音指令（可选，需要额外装识别引擎）

CrewChief 支持用语音向工程师提问（「胎压多少」「前面差多少」）。这部分是识别不是播报， 和语音包完全独立。

  1. 装中文识别引擎，二选一。两条路都支持并会自动回落，但识别门槛差一倍：
    引擎置信度阈值
    Microsoft Speech Platform —— MSSpeech_SR_zh-CN_TELE.msi0.5
    Windows 自带 —— 设置 → 时间和语言 → 语言 → 添加中文，勾「语音识别」0.75

    实测 Windows 自带引擎在中文上表现已经够好（常见指令 0.92～0.99），不必特意去装 MSSpeech。

  2. 把 speech_recognition_override.txt 放进 CrewChief 的数据文件夹，文件名不要改。

    ⚠ 不要照着「我的文档\CrewChiefV4\」去猜路径

    如果你把「我的文档」重定向到了别的盘（很常见），那个路径根本不存在。让程序自己带你去： 菜单「文件」→「Open data files folder」，打开的就是程序实际使用的数据目录。
  3. 打开语音识别
    主界面上的「语音识别模式」下拉框，选：
    始终启用最省事，不用分配按键，适合先试通
    按住按钮需要先分配一个按键，实际使用推荐这个

    ⚠「触发词」和「按下并松开按钮」在 nAudio 开启时不可用，选了也没用， 而 nAudio 默认是开的。

  4. 重启 CrewChief

    日志顶部的 VOICE_OPTION 应该从 DISABLED 变成 ALWAYS_ON 或 HOLD，没变说明没生效。

共 45 条常用指令：车况、胎温胎压、油量电量、位置差距、圈速，以及「安静」「再说一遍」这类控制。 建议先试「能听到吗」——它不需要在赛道上，也不依赖任何游戏数据，是最快确认链路通了的一条。

怎么验证识别效果

用菜单「语音向导」。说一句指令，它会实时显示：

Recognised text: 胎压多少
Volume: 0.42
Confidence: 0.921

没听出来就显示 Nothing recognised。这比在比赛里瞎试高效得多——你能立刻看到它听成了什么、 置信度多少。控制台也会同步记录每一次识别及其置信度。

顺带一句：置信度门槛是会自适应的。CrewChief 按接受／拒绝比动态调整，还能识别出 「用户重念了一遍」并主动降低门槛，所以用得越久越准。第一次念被拒是正常的，重念一遍通常就过了。

为什么只有 45 条，而不是全部 1300 条？

CrewChief 的识别是「短语列表精确匹配」，中文同音字太多（进站/近站、四/是）， 指令越多误识别越严重。程序自己的配置文件注释也建议删减指令。

这个覆盖文件会整份替换默认配置，没列出来的指令就不再监听—— 这正是该机制的设计意图，不是缺陷。

启动时那条 Number strings 警告是预期的，不是装错了 Warn: Number strings not available. It is likely that you have a custom speech_recognition_override.txt which does not include the default values. All voice commands, including macros, that use numbers will be disabled.

原因是整份替换之后，上游配置里那 1099 条数字读法（键名就是 "0"、"1" …… "199"）也一起没了。

本包这 45 条指令没有一条用到数字，所以对它们零影响。真正被禁掉的是：带数字的命令宏、 「P5 是谁」这类按名次提问、以及车号相关指令。如果你需要这些，得自行往这个文件里补 0～199 的中文读法 （代价是语法变大，可能拉低识别率）。

说「开启／关闭观察员」时日志报 ERROR，但指令其实生效了 ERROR: Speech command 开启观察员 not handled

指令是生效的——spotter 会开关，应答音也会播。这是上游的一个小 bug： SpeechRecogniser.cs 里这两条指令干完活之后返回了 null，调用方把 null 当成「没处理」。

英文版说 spotter on 会报一模一样的错，与中文包无关，忽略即可。

⑤ 中文字幕覆盖层（可选）

本包每个语音文件夹里都带了 subtitles.csv，字幕文本是中文，所以打开覆盖层就能在游戏里 看到工程师说的每一句中文。不想要可以跳过。

  1. 打开它
    属性页搜 subtitle，勾上「启用字幕覆盖层」，保存，重启。

    这一项默认是关闭的，所以「装了包却没看到字幕」是正常的，不是坏了—— 得先自己打开。它标了 RESTART_REQUIRED，不重启不生效。

  2. 把那一大片设置面板收起来
    覆盖层第一次出现时会连带显示一整块设置控件，挡住画面。两个办法：
    按 Ctrl + Shift立刻收起／展开。这是运行时开关，界面上没写
    勾「Hide controls on startup」
    再点「Save settings」    		下次启动就是收起状态

    勾选本身不会立刻隐藏——那个值只在启动时读一次。所以勾完再按一次 Ctrl+Shift。

    ⚠ 别点右上角那个 ⊠

    它不是收起控件，是把整个覆盖层关掉（字幕一起消失），要重启 CrewChief 才回来。

    另外游戏里别勾「Enable input」——勾了之后鼠标移到覆盖层上点击会抢走 窗口焦点，游戏会失去输入。只在调整设置时临时勾。

    面板上的「Max history」是同屏显示的历史行数，只想看当前一句就改成 1。

字体：实测 Windows 中文环境下默认字体就能正常显示汉字，一般不用动。万一显示成方块， 改这个文件里的 "fontName"：

我的文档\CrewChiefV4\subtitle_overlay.json
"fontName": "Microsoft YaHei",

工程师覆盖层是同一套设置，文件叫 crewchief_overlay.json，同样改法。两个 json 都是 CrewChief 首次运行时自动生成的，找不到就先启动一次。改完重启生效，不需要重新编译。

⚠ 覆盖层控件上的英文改不了

Window width、Bold font、Save settings 这些字符串是硬编码在 Overlay/SubtitleOverlay.cs 里的， 不走界面文案那套机制，本包的界面中文化覆盖不到，只能重新编译程序才能改。 字幕正文不受影响，正文是中文的。

注意事项

原版程序装了 numbers/ 会中英混播

numbers 包会覆盖 numbers/0–99、point、hour 这些英文包已有的文件夹，但它没有英文特有的 928 个合成件——其中 599 个是 45point6 这类「数字point数字」，另外还有 point75、1_23（分_秒）等预录整段读音。

结果就是圈速播报里整数部分念中文、小数部分念英文，变成「四十五 point six」。

为什么中文需要改程序才能念数字

CrewChief 的数字朗读规则写死在代码里，每种语言一个实现类 （NumberProcessing/NumberReader.cs 定义了 10 个抽象方法），上游自带 en / it / pt-br，没有中文。

中文规则和这三种都不一样——「二」和「两」要分场合、万是独立量级、「一分二十三秒四」的结构也不同—— 所以需要新增一个 NumberReaderZh.cs。

不要装到 alt\ 目录

CrewChief 在使用非默认工程师语音包时，会强制从基础包读取 spotter 和 radio_check（见 Audio/Sounds.cs 里 prepareVoiceWithoutLoading 的实现）。

后果是工程师说中文、spotter 永远说英文——而 spotter 恰恰是比赛中出现频率最高的播报。 所以正确装法是上面写的「整包替换 + Override 路径」，而且第 7 步要确认两个下拉框都是默认值。

关于自动更新

先说清楚：CrewChief 不会在后台静默覆盖你的语音包。它只是把主界面上的语音包下载按钮点亮， 要你自己点了才会下载覆盖。所以最坏情况是「哪天顺手点了绿按钮」，不是开着开着就没了。

按钮什么时候会变绿

判断是 latest > current：current 读你语音包根目录的 sound_pack_version_info.txt，latest 从上游 XML 里按语言取。

装法处境
用法 B（有 zh 语言标记） 查 zh 段，上游没有这一段，取不到更新包，按钮永远是灰的。天然免疫。
用法 A（没有语言标记） 语言为空时代码按 en 查，拿到真实的英文包版本号，上游一发新版按钮就变绿。 所以第 6 步要把 current 撑大到 9999。

⚠ 启动参数 -skip_updates 不管用

它只跳过程序本体的更新检查，语音包的 XML 照样下载和比对。别拿它当防线。

哪些内容有意保留英文

下面这些整个文件夹不在包里，装上后自动播原来的英文原音。这是有意为之，不是漏做。

内容例子
车手名、弯角名Hamilton、Eau Rouge、130R —— 中文车手本来也说原名
车辆组别号GT3、GT300、LMP2、DTM、Group C
超车辅助DRS、KERS、push-to-pass 整个分类

除了「本来就说英文」，还有个实际原因：中文语音引擎念拉丁字母不可靠。实测 GTC 三个字母能念到 1.73 秒，DRS 在句子里只占 0.25 秒。与其念不清楚，不如用原音。

怎么确认装好了

语音

  • 启动时的无线电测试是中文
  • 进游戏后有车贴近时的盲区提醒是中文
  • 工程师播报是中文：旗语、圈数、燃油、轮胎、罚则、进站……
  • 车手名、弯角名、GT3 这类组别号仍是英文 —— 正常
  • 用法 A：圈速里的数字仍是英文（「one twenty-three point four」）
  • 用法 B：数字也是中文（「一分二十三秒四」），问「现在几点」念「上午八点零五分」

界面（装了 ui_text.txt 才有）

  • 主界面按钮、菜单栏是中文
  • 属性页里设置项名称和帮助文本是中文
  • 有一类设置项的值仍是 UI_STARTUP_AND_PATHS 这种全大写英文 —— 正常

语音指令（装了覆盖文件 + 中文识别引擎才有）

  • 说「能听到吗」能被识别 —— 不用进游戏，最快的一条
  • 用「语音向导」看置信度：常见指令应该在 0.9 以上，0.7 以上都算正常
  • 日志里出现 Got SRE for zh-CN，说明中文识别引擎加载成功了

⚠ 播报比想象的少，不一定是故障

很多人第一次测会觉得「怎么半天不说话」。CrewChief 的播报量取决于会话类型和 场上车数，差别很大：

练习赛 + 场上只有一两台车几分钟只有零星几条，这是正常的
正赛 + 十来台车几十秒就会有一批

练习赛里没有名次变化、没有超车、没有差距可报，本来就没什么可说的。要判断语音包是否正常， 用正赛 + 多台 AI，别用练习赛。

另外圈速播报是按频率概率触发的（属性 frequency_of_player_race_lap_time_reports 默认 4/10），跑一圈有六成概率不报。 想尽快听到就把它临时调到 10，或者开练习赛多跑几圈（练习赛那个参数默认 6/10，报得更勤）。

真正说明有问题的是日志里出现 can't be played——那才是缺文件夹。

卸载

装的东西卸载方法
语音属性页里 Override default Sound Pack location 清空，重启。
用法 B 还要把 sound_pack_language.txt 改回 en 或删掉。
界面删掉 %LOCALAPPDATA%\CrewChiefV4\ui_text.txt，重启
语音指令删掉 我的文档\CrewChiefV4\speech_recognition_override.txt，重启
三样互相独立，可以只卸其中一样。原来的语音包目录始终没被改过，所以随时能退回英文。

源码改动在项目仓库，一个新文件加四处小改：

文件改动
CrewChiefV4/NumberReaderZh.cs新增，中文数字朗读实现

CrewChiefV4.csproj编译新文件

后两处是「现在几点」的播报。不打这个补丁的话，中文包会把 8:05 念成「八 零 五 上午」—— 片段是对的，语序是英文的。打上之后是「上午八点零五分」。

补丁文件：patches/crewchief-zh-numberreader.diff。需要 Windows + Visual Studio / msbuild 自行编译，配置选 Release | x86。启动后日志里应该出现：

Using NumberReaderZh for soundPackLanguage zh

没有这行说明语言标记没读到，检查 sound_pack_language.txt 的位置和内容。
