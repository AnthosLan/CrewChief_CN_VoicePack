## 二、已验证的生成方案

### 2.1 定稿参数

```bash
scripts/pilot_mac.py \
  --phrase_inventory <翻译后的CSV> \
  --language zh-cn \
  --baseline_audio_dir baseline/Bart \
  --xtts_speed 1.45 \
  --eq_preset radio \
  --voice_name <输出名>
```

> 完整可执行命令见 §12。

| 参数 | 值 | 依据 |
|---|---|---|
| 音色 | **Bart** | ElevenLabs 合成音色，**不涉及真人声纹**。从官方 1.2GB 完整包 30714 个文件里筛出 12 条干净片段，共 **38.9 秒** baseline |
| 语言码 | `zh-cn` | XTTS v2 官方支持的 17 语言之一 |
| 语速 | **1.45x** | 实测 **188ms/音节**，普通话正常语速区间（170–200ms）。1.6x（149ms）偏快，长句压到 132ms 会糊 |
| EQ | **radio** | 原项目曲线，试听确认 |
| 变体数 | 1（`--variation_count 0/1`） | CrewChief 会在同文件夹内轮换变体，双变体可减少机械感，代价是时间翻倍 |

### 2.2 音频格式（与 CrewChief 语音包一致）

**单声道 / 22050 Hz / 16-bit PCM**，峰值归一到 −1 dBFS，首尾静音已裁。

### 2.3 被否决的方案及原因

| 方案 | 结果 | 原因 |
|---|---|---|
| macOS 原生中文 TTS 做 baseline | ❌ 更差 | 共振峰合成的机械感被一起克隆进去；`收到` 出现 576ms/音节 的拖音异常 |
| CrewChief 自带真人语音做 baseline | ❌ 放弃 | 效果不佳，且涉及署名个人（Geoffrey Lessel、Matt Orr 等）的声纹 |
| warm / full / broadcast EQ | ❌ 未采用 | 试听后选定 radio |
| baseline 从 14 秒扩到 39 秒 | ⚠️ 收益有限 | 音高标准差仅从 37.0Hz 降到 32.7Hz（−12%），XTTS conditioning 在 15 秒左右接近饱和。但成本已付，保留 |

## 四、AC-only 带来的简化（已验证）

[CrewChief.cs:390-413](CrewChiefV4/CrewChief.cs:390) 按游戏裁剪事件模块，AC 会移除：

| 被移除的模块 | 收益 |
|---|---|
| **`PitManagerVoiceCmds`**（仅 RF2/LMU 加载） | ✅ **`SpokenNumberParser` 无需改造**。它按空格切词 + 硬编码英文数词，中文完全失效，但全项目仅 3 处调用且全在 PitManager。AC 不加载 → 省掉这处代码改动 |
| `IRacingBroadcastMessageEvent` | iRacing 专属指令不用翻译 |
| `Ratings`（iRacing/R3E 专属） | iRating / 安全等级相关不用翻译 |
| `CoDriver`（拉力专属） | 419 条路书文案不用做 |

⚠️ **注意**：语音指令的**语法本身基本不分游戏**——[SpeechRecogniser.cs](CrewChiefV4/SpeechRecogniser.cs) 里只有 6 处 `Game.XXX` 判断。所以「只做 AC」对指令翻译量减少有限，主要省的是代码改动和拉力部分。

### 5.1 autovoicepack 侧（✅ 已完成，分支 `zh-cn-support`）

| 文件 | 改动 | 原因 |
|---|---|---|
| `generate_voice_pack.py` | `model.inference(text, "en", ...)` → `language` 参数化，新增 `--language`（17 语言校验） | **语言码原本硬编码为 `en`**，中文文本走英文 tokenizer 出不了可用结果 |

### 6.2 翻译执行

排除 corners/numbers/codriver 后：**5244 行 → 3701 条不重复文案**（缓存生效后的实际 LLM 调用量）。

```bash
python3 translate_phrases.py \
  --target_language "Simplified Chinese" \
  --model qwen2.5:14b \
  --translated_phrase_inventory $PACK/translations/phrase_inventory_zh.csv \
  --skip_sanity_check
```

⚠️ **不要用 qwen2.5:32b**：19GB 模型在 16GB 内存的 M1 上会疯狂 swap。用 `qwen2.5:14b`（约 9GB）或云端 API。

## 七、安装与防覆盖

### 7.1 ⚠️ 不要装到 `alt/` 目录

CrewChief 在使用非默认工程师语音包时，会**强制**从基础包读取 `spotter*` 和 `radio_check*`（[Sounds.cs:1147-1162](CrewChiefV4/Audio/Sounds.cs:1147)）：

```
选了 alt 语音包 + 公路赛：
  spotter* / radio_check*  →  强制从【基础包】读（英文）
  其余所有 voice 文件夹     →  从 alt 包读
```

按 autovoicepack README 的装法（拷到 `Sounds\alt\`），结果是**工程师说中文、spotter 永远说英文**——而 spotter 恰恰是比赛中出现频率最高的播报。

### 7.2 正确装法

```
1. 复制基础语音包目录             %LOCALAPPDATA%\CrewChiefV4\Sounds  →  Sounds_zh
2. 把中文 voice/ 覆盖上去
3. 设置 override_default_sound_pack_location = <Sounds_zh 路径>
4. chief_name 保持默认（不触发 alt 重定向）
5. sounds/sound_pack_language.txt 内容改为  zh
6. sounds/sound_pack_version_info.txt 版本号设成很大的值（防自动更新覆盖）
```

这样整包替换，spotter 也是中文，同时躲开自动更新。启动参数可加 `-skip_updates` 双重保险。

### 7.3 其他配置

| 项 | 值 | 原因 |
|---|---|---|
| `ui_language` | `zh` | 加载 `ui_text/zh.txt`（`Configuration` 自动合并到 `en.txt` 之上） |
| Overlay `fontName` | 微软雅黑 / 思源黑体 | 默认 `Arial` 无中文字形，字幕会显示方块 |
| `speech_recognition_config.txt` 的 `language` | `zh` | 仅做语音指令时需要 |
| `speech_recognition_country` | `CN` | 同上 |

## 八、语音指令（可后置）

**不需要录任何音频**——这是识别（输入），与播报完全解耦。但也不只是翻译：

| 层面 | 内容 | 量 |
|---|---|---|
| 翻译 | `speech_recognition_config.txt`：**423 个指令 key / 781 条短语** + 1099 个数字 key / 1498 条短语 | 数字部分高度规律，可脚本生成 |
| 引擎 | 装 `MSSpeech_SR_zh-CN_TELE.msi`（MS Speech Platform）或 Windows 中文语音识别包 | 找不到会弹窗报错 |
| 代码 | ✅ AC 无需改动（见 §4） | |

⚠️ **现实问题**：这套架构的语法是「短语列表精确匹配」（`GrammarBuilder` + `Choices`）。中文同音字极多（进站/近站、四/是），423 个指令 × 多个变体全塞进一个语法，误识别率会显著上升。

**建议只保留 30–50 个高频指令**，而不是全量翻译 781 条。配置文件注释本身也提到删减指令能大幅提升识别质量。

## 十、环境搭建（M1 实测）

Docker 镜像基于 `nvidia/cuda` + amd64，Apple Silicon 无法使用。venv 建在 autovoicepack 目录下（本库不放二进制依赖）：

```bash
cd ~/Projects/crew-chief-autovoicepack
python3 -m venv .venv
.venv/bin/pip install coqui-tts
.venv/bin/pip install "transformers>=4.57,<5"
.venv/bin/pip install "torch<2.9" "torchaudio<2.9"
.venv/bin/pip install jieba pypinyin
```

**四个依赖坑（按顺序踩到）：**

| 现象 | 原因 | 解法 |
|---|---|---|
| `No module named 'torch'` | coqui-tts 0.27 不再声明 torch 依赖（让用户自选 CUDA/CPU 版本） | 单独装 |
| `cannot import name 'isin_mps_friendly'` | transformers 5.x 移除了该函数 | 降到 4.57.x |
| `torchcodec library is required` | torch 2.9+ 强制要 torchcodec，而它又要系统装 ffmpeg | 降到 torch 2.8 规避 |
| XTTS 中文分支报错 | 缺中文 g2p 依赖 | 装 `jieba` `pypinyin` |

生成速度（M1 / MPS）：短句 1.6–2.1 秒/条，长句 2.5–3.2 秒/条。

## 十一、风险与未决项

| 风险 | 影响 | 应对 |
|---|---|---|
| **XTTS 中文音色带英文口音** | 听感 | 已知问题，Bart 音色可接受。彻底解决需真人中文录音做 baseline |
| **数字/时间拼接韵律** | 圈速、差距播报听起来生硬 | `NumberReaderZh` 必须先设计定稿再生成音频 |
| **短句不稳定** | 2–4 音节的 `安全`、`还在` 等 | XTTS 在极短文本上方差大，必要时单独重跑或调 `--xtts_speed` |
| **单变体机械感** | 同一句反复听会腻 | 原包每文件夹 2–7 个变体轮换，中文包可用 `--variation_count 1` 做双变体 |
| **XTTS 非商用许可** | 分发受限 | 公开分发前确认；或换国内商用 TTS（本方案的 inventory / 目录结构 / 后处理链均可复用） |
| 中文语音识别率 | 语音指令可用性 | 砍到 30–50 个高频指令 |

### 生成脚本的两个中文专属参数

短文本（一两个汉字）是 XTTS 最不稳的地方 —— 会在音节前后补一段幻觉音，或者干脆把音节念两遍。
两道防线，都只对短句生效，长句不受影响：

| 参数 | 默认 | 作用 |
|---|---|---|
| `--artifact_trim_max_syllables` | 4 | 音节后若出现 ≥250ms 的近静音间隙，其后的内容判为幻觉音，裁掉 |
| `--attempts` / `--attempts_max_syllables` | 1 / 6 | 生成多个候选取最短的合格者。所有失败模式都让音频变长，所以最短的那个基本就是对的 |

数字包用 `--attempts 5` 生成。工程师那 3772 条大多是整句，稳定得多，默认 1 次即可。
