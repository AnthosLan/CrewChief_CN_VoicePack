## 二、已验证的生成方案

### 2.1 定稿参数

```bash
scripts/pilot_mac.py \
  --phrase_inventory <翻译后的CSV> \
  --language zh-cn \
  --baseline_audio_dir baseline/Bart \
  --xtts_speed 1.45 \
  --eq_preset radio \
  --voice_name <输出名>
```

> 完整可执行命令见 §12。

| 参数 | 值 | 依据 |
|---|---|---|
| 音色 | **Bart** | ElevenLabs 合成音色，**不涉及真人声纹**。从官方 1.2GB 完整包 30714 个文件里筛出 12 条干净片段，共 **38.9 秒** baseline |
| 语言码 | `zh-cn` | XTTS v2 官方支持的 17 语言之一 |
| 语速 | **1.45x** | 实测 **188ms/音节**，普通话正常语速区间（170–200ms）。1.6x（149ms）偏快，长句压到 132ms 会糊 |
| EQ | **radio** | 原项目曲线，试听确认 |
| 变体数 | 1（`--variation_count 0/1`） | CrewChief 会在同文件夹内轮换变体，双变体可减少机械感，代价是时间翻倍 |

### 2.2 音频格式（与 CrewChief 语音包一致）

**单声道 / 22050 Hz / 16-bit PCM**，峰值归一到 −1 dBFS，首尾静音已裁。

### 2.3 被否决的方案及原因

| 方案 | 结果 | 原因 |
|---|---|---|
| macOS 原生中文 TTS 做 baseline | ❌ 更差 | 共振峰合成的机械感被一起克隆进去；`收到` 出现 576ms/音节 的拖音异常 |
| CrewChief 自带真人语音做 baseline | ❌ 放弃 | 效果不佳，且涉及署名个人（Geoffrey Lessel、Matt Orr 等）的声纹 |
| warm / full / broadcast EQ | ❌ 未采用 | 试听后选定 radio |
| baseline 从 14 秒扩到 39 秒 | ⚠️ 收益有限 | 音高标准差仅从 37.0Hz 降到 32.7Hz（−12%），XTTS conditioning 在 15 秒左右接近饱和。但成本已付，保留 |

## 四、AC-only 带来的简化（已验证）

[CrewChief.cs:390-413](CrewChiefV4/CrewChief.cs:390) 按游戏裁剪事件模块，AC 会移除：

| 被移除的模块 | 收益 |
|---|---|
| **`PitManagerVoiceCmds`**（仅 RF2/LMU 加载） | ✅ **`SpokenNumberParser` 无需改造**。它按空格切词 + 硬编码英文数词，中文完全失效，但全项目仅 3 处调用且全在 PitManager。AC 不加载 → 省掉这处代码改动 |
| `IRacingBroadcastMessageEvent` | iRacing 专属指令不用翻译 |
| `Ratings`（iRacing/R3E 专属） | iRating / 安全等级相关不用翻译 |
| `CoDriver`（拉力专属） | 419 条路书文案不用做 |

⚠️ **注意**：语音指令的**语法本身基本不分游戏**——[SpeechRecogniser.cs](CrewChiefV4/SpeechRecogniser.cs) 里只有 6 处 `Game.XXX` 判断。所以「只做 AC」对指令翻译量减少有限，主要省的是代码改动和拉力部分。

## 六、翻译方案

### 6.1 语料来源

| 来源 | 覆盖 | 说明 |
|---|---|---|
| autovoicepack `phrase_inventory.csv` | 9145 行 / 3273 文件夹，覆盖当前包 **84%**（3261/3862） | 对着旧版语音包做的，缺新增内容 |
| CrewChief 自带 `subtitles.csv` | 2956 个文件 / 10415 行，**100%** | 每个语音文件夹都有 `wav名,"英文原文"`，是权威台本。`extra/generate_phrase_inventory.py` 可从中生成 inventory |

**建议用后者重新生成 inventory**，保证覆盖完整。

### 6.2 翻译执行

排除 corners/numbers/codriver 后：**5244 行 → 3701 条不重复文案**（缓存生效后的实际 LLM 调用量）。

```bash
python3 translate_phrases.py \
  --target_language "Simplified Chinese" \
  --model qwen2.5:14b \
  --translated_phrase_inventory $PACK/translations/phrase_inventory_zh.csv \
  --skip_sanity_check
```

⚠️ **不要用 qwen2.5:32b**：19GB 模型在 16GB 内存的 M1 上会疯狂 swap。用 `qwen2.5:14b`（约 9GB）或云端 API。

### 6.3 术语表（已确认）

| 英文 | 中文 | 备注 |
|---|---|---|
| 3 wide | **三辆并排** | 不用「三宽」 |
| clear / all clear | **安全** / 都安全 | 不用「空了」 |
| inside / outside | 内线 / 外线 | 走线位置 |
| low / high | 内侧 / 外侧 | 相对高低 |
| box now | 进站 | |
| safety car | 安全车 | |
| hold your line | 保持走线 | |

翻译完必须人工过一遍赛车术语，机器翻译在这块不可靠。

### 6.4 语料 CSV 格式

沿用 autovoicepack 的 inventory 格式，5 列，UTF-8：

```csv
audio_path,audio_filename,subtitle,text_for_tts,original_english
\voice\spotter\car_left,1.wav,左边有车,左边有车,car left
```

| 列 | 含义 |
|---|---|
| `audio_path` | 输出路径，**每一段都是 CrewChief 播报逻辑里的标识符** |
| `audio_filename` | 同一文件夹内的变体编号，CrewChief 轮换播放 |
| `subtitle` | 字幕文本，写入 `subtitles.csv`，覆盖层显示用 |
| `text_for_tts` | 送进 XTTS 的文本，通常与 `subtitle` 相同 |
| `original_english` | 英文原文，人工校对时对照用，不参与生成 |

⚠️ **文件夹名不能翻译。** `audio_path` 的每一段（`spotter/car_left`、`numbers/ten_thousand`）都要与英文包的目录结构**逐字对应**——那是播报逻辑里的标识符，不是描述性名字。写错了这条消息永远不会播，而且不报错。只有 `subtitle` 和 `text_for_tts` 是中文。

`YOUR_NAME` 是占位符，生成时被 `--your_name` 替换。翻译时不能连它一起译掉——LLM 经常这么干，`translate_phrases.py` 为此加了占位符保护与丢失告警（见 §5.1）。

## 七、安装与防覆盖

### 7.1 ⚠️ 不要装到 `alt/` 目录

CrewChief 在使用非默认工程师语音包时，会**强制**从基础包读取 `spotter*` 和 `radio_check*`（[Sounds.cs:1147-1162](CrewChiefV4/Audio/Sounds.cs:1147)）：

```
选了 alt 语音包 + 公路赛：
  spotter* / radio_check*  →  强制从【基础包】读（英文）
  其余所有 voice 文件夹     →  从 alt 包读
```

按 autovoicepack README 的装法（拷到 `Sounds\alt\`），结果是**工程师说中文、spotter 永远说英文**——而 spotter 恰恰是比赛中出现频率最高的播报。

### 7.2 正确装法

```
1. 复制基础语音包目录             %LOCALAPPDATA%\CrewChiefV4\Sounds  →  Sounds_zh
2. 把中文 voice/ 覆盖上去
3. 设置 override_default_sound_pack_location = <Sounds_zh 路径>
4. chief_name 保持默认（不触发 alt 重定向）
5. sounds/sound_pack_language.txt 内容改为  zh   （仅打了补丁的构建，见下）
6. 没写第 5 步的话，sounds/sound_pack_version_info.txt 版本号设成很大的值
```

这样整包替换，spotter 也是中文。

**防覆盖的实际机制**（写进 INSTALL.txt 的「关于自动更新」一节，措辞对使用者更直白）：

CrewChief 不会静默覆盖，它只把语音包下载按钮点亮，用户点了才下载。按钮亮不亮看
`latest > current`（[SoundPacks.cs:117](CrewChiefV4/UserInterface/SoundPacks.cs:117)），`current` 取自语音包根目录的
`sound_pack_version_info.txt`，`latest` 按**语言**从上游 XML 取：

| 语言标记 | 取到什么 | 结果 |
|---|---|---|
| `zh`（第 5 步） | 上游 XML 没有 zh 段，`voiceMessageUpdatePacks` 为空 | 按钮永远灰，天然免疫 |
| 空（原版程序） | [MainWindow.cs:607](CrewChiefV4/UserInterface/MainWindow.cs:607) 的 `soundPackLanguage == null ? "en"` 回落到 en，拿到真实英文版本号 | 上游一发新版按钮就绿，需要第 6 步撑大 `current` |

⚠️ `-skip_updates` **不能**当防线。它只跳过 `AutoUpdater.Start()`（程序本体更新），语音包的
XML 照样下载解析（[MainWindow.cs:598-608](CrewChiefV4/UserInterface/MainWindow.cs:598)）。

### 7.3 其他配置

| 项 | 值 | 原因 |
|---|---|---|
| `ui_language` | `zh` | 加载 `ui_text/zh.txt`（`Configuration` 自动合并到 `en.txt` 之上） |

## 八、语音指令（可后置）

⚠️ **现实问题**：这套架构的语法是「短语列表精确匹配」（`GrammarBuilder` + `Choices`）。中文同音字极多（进站/近站、四/是），423 个指令 × 多个变体全塞进一个语法，误识别率会显著上升。

**建议只保留 30–50 个高频指令**，而不是全量翻译 781 条。配置文件注释本身也提到删减指令能大幅提升识别质量。

## 十、环境搭建（M1 实测）

Docker 镜像基于 `nvidia/cuda` + amd64，Apple Silicon 无法使用。venv 建在 autovoicepack 目录下（本库不放二进制依赖）：

```bash
cd ~/Projects/crew-chief-autovoicepack
python3 -m venv .venv
.venv/bin/pip install coqui-tts
.venv/bin/pip install "transformers>=4.57,<5"
.venv/bin/pip install "torch<2.9" "torchaudio<2.9"
.venv/bin/pip install jieba pypinyin
```

**四个依赖坑（按顺序踩到）：**

| 现象 | 原因 | 解法 |
|---|---|---|
| `No module named 'torch'` | coqui-tts 0.27 不再声明 torch 依赖（让用户自选 CUDA/CPU 版本） | 单独装 |
| `cannot import name 'isin_mps_friendly'` | transformers 5.x 移除了该函数 | 降到 4.57.x |
| `torchcodec library is required` | torch 2.9+ 强制要 torchcodec，而它又要系统装 ffmpeg | 降到 torch 2.8 规避 |
| XTTS 中文分支报错 | 缺中文 g2p 依赖 | 装 `jieba` `pypinyin` |

生成速度（M1 / MPS）：短句 1.6–2.1 秒/条，长句 2.5–3.2 秒/条。

### 翻译环境（ollama，第二阶段才需要）

XTTS 那套 venv 与 ollama 互不相干，装不装 ollama 不影响生成音频。

```bash
brew install ollama
brew services start ollama        # 或前台跑 ollama serve
ollama pull qwen2.5:14b           # 约 9GB
```

⚠️ **不要用 `qwen2.5:32b`**：19GB 模型在 16GB 内存的 M1 上会疯狂 swap。

`translate_phrases.py` 的 `--ollama_host` 默认是 `host.docker.internal:11434`（给 Docker 用的），
本机直接跑必须显式传 `localhost:11434`，否则连不上。

⚠️ XTTS v2 首次运行下载约 1.9GB 模型，需接受 **Coqui CPML 许可（非商用）**，`COQUI_TOS_AGREED=1` 可非交互接受。

## 十一、风险与未决项

| 风险 | 影响 | 应对 |
|---|---|---|
| **XTTS 中文音色带英文口音** | 听感 | 已知问题，Bart 音色可接受。彻底解决需真人中文录音做 baseline |
| **数字/时间拼接韵律** | 圈速、差距播报听起来生硬 | `NumberReaderZh` 必须先设计定稿再生成音频 |
| **短句不稳定** | 2–4 音节的 `安全`、`还在` 等 | XTTS 在极短文本上方差大，必要时单独重跑或调 `--xtts_speed` |
| **单变体机械感** | 同一句反复听会腻 | 原包每文件夹 2–7 个变体轮换，中文包可用 `--variation_count 1` 做双变体 |
| **XTTS 非商用许可** | 音频不能商用、不能改成 MIT | 免费开源分发可以，照 §13 的三个条件办；要商用则换 TTS 引擎（本方案的 inventory / 目录结构 / 后处理链均可复用） |
| **baseline 音色的来源条款** | 比 CPML 更容易被忽略 | Bart 是 ElevenLabs 合成音，见 §13.2。彻底规避只需重录 39 秒自己的 baseline |
| 中文语音识别率 | 语音指令可用性 | 砍到 30–50 个高频指令 |

### 生成脚本的两个中文专属参数

短文本（一两个汉字）是 XTTS 最不稳的地方 —— 会在音节前后补一段幻觉音，或者干脆把音节念两遍。
两道防线，都只对短句生效，长句不受影响：

| 参数 | 默认 | 作用 |
|---|---|---|
| `--artifact_trim_max_syllables` | 4 | 音节后若出现 ≥250ms 的近静音间隙，其后的内容判为幻觉音，裁掉 |
| `--attempts` / `--attempts_max_syllables` | 1 / 6 | 生成多个候选取最短的合格者。所有失败模式都让音频变长，所以最短的那个基本就是对的 |

数字包用 `--attempts 5` 生成。工程师那 3772 条大多是整句，稳定得多，默认 1 次即可。

## 十三、许可与分发

> 以下是对许可文本的阅读理解，不是法律意见。权威文本：[Coqui Public Model License 1.0.0](https://huggingface.co/coqui/XTTS-v2/raw/main/LICENSE.txt)。

### 13.1 CPML：开源不解除许可

常见误解是「开源了就不受约束」。**不成立。** CPML 定义的「使用」涵盖模型**及其输出**，
生成出来的音频跟模型权重受同一份许可管，与收不收钱无关。收费与否决定的是「你的用途算不算商用」，
不决定「许可管不管得着这些音频」。

好消息是 CPML 的非商用定义明确包含个人研究、私人娱乐、业余项目——**一个免费的游戏语音包落在这一侧，
可以公开发布**。三个硬条件：

| # | 条件 | 落实方式 | 状态 |
|---|---|---|---|
| 1 | **必须传递条款**：任何从你这里拿到副本的人也要拿到 CPML 全文 | `packaging/CPML.txt` 逐字存档，`build_release.sh` 打进 zip 根目录；文件缺失直接报错退出 | ✅ 已落实 |
| 2 | **音频不能改成 MIT**：CPML 不允许 sublicense 或转让许可 | README 与 INSTALL.txt 保持「语料与脚本 MIT / 生成音频受上游约束」的分层写法，别合并 | ✅ 已如此 |
| 3 | **下游同样不能商用** | 写明别人不能把本包塞进付费产品或付费整合包 | ✅ 已写明 |

边界提醒：接受赞助/捐赠、挂在靠广告变现的站点，都会往商业化那侧滑。Coqui 已于 2024 年 1 月关停，
既没人能卖商业许可，实际也没人执行——但「没人管」不等于「合法」，风险自负。

### 13.2 容易漏掉的第二层：baseline 音色的来源条款

Bart 不是 CPML 的问题，是**另一份条款**。autovoicepack 的 baseline 来自 ElevenLabs
（其 README 的 `record_elevenlabs_voice.py` 一节就是教你从 ElevenLabs 拉 baseline），
而 ElevenLabs 的服务条款通常禁止用其输出去训练或克隆到其他语音模型——
「拿它当 XTTS 的 voice cloning baseline」正好在这个措辞的射程内。

autovoicepack 仓库是 MIT，但 MIT 覆盖的是代码，覆盖不了上游服务的条款。这条与开不开源无关，
但公开分发会放大可见度。**分发前自行核对 ElevenLabs 现行条款；若要彻底规避，重录 39 秒自己的 baseline 即可**——
只换 `baseline/` 里那 12 个 wav，全链路其余部分不动。

### 13.3 要商用怎么办

换 TTS 引擎。语料 CSV、目录结构、`NumberReaderZh`、后处理链全部可复用，要换的只有 baseline 和推理那一步。
国产开源里 CosyVoice 2（阿里）等走 Apache-2.0 路线，但**具体权重的许可要自己逐个核实**，别信二手说法——
不少模型是「代码 Apache、权重 CC-BY-NC」的双轨制，跟 XTTS 是同一个坑。
