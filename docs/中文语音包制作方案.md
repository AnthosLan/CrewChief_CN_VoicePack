# CrewChief 中文语音包制作方案

> 目标游戏：**Assetto Corsa**（AC）
> 制作工具：**crew-chief-autovoicepack**（已 fork 改造，方案已实测验证）
> 里程碑：**v1.0.0 Beta** —— 制作内容全部完成，Windows 验收七项已过五项

**Beta 的含义**：语音、界面、语音指令、字幕四块已在 Windows + AC 上实跑通过
（详见[踩坑与经验总结 §8.1](踩坑与经验总结.md)），剩下两项只影响「让圈速数字也说中文」这个
增量功能，需要自己编译程序。

仍标 Beta 而不是正式版的理由是**抽样通过不等于全量通过**：5308 条语音只实听了几十条，
1305 条文案只翻了几页。**「脚本能证明格式对，证明不了说得通」**这句话仍然成立，
只是适用范围小了——译文别扭这类问题只能靠使用者反馈。

**本文只写流程、参数与方案**——怎么做、做多少、跑哪条命令。三类内容已拆出去：

## 二、已验证的生成方案

### 2.1 定稿参数

```bash
scripts/pilot_mac.py \
  --phrase_inventory <翻译后的CSV> \
  --language zh-cn \
  --baseline_audio_dir baseline/Bart \
  --xtts_speed 1.45 \
  --eq_preset radio \
  --voice_name <输出名>
```

> 完整可执行命令见 §11。

| 参数 | 值 | 依据 |
|---|---|---|
| 音色 | **Bart** | ElevenLabs 合成音色，**不涉及真人声纹**。从官方 1.2GB 完整包 30714 个文件里筛出 12 条干净片段，共 **38.9 秒** baseline |
| 语言码 | `zh-cn` | XTTS v2 官方支持的 17 语言之一 |
| 语速 | **1.45x** | 实测 **188ms/音节**，普通话正常语速区间（170–200ms）。1.6x（149ms）偏快，长句压到 132ms 会糊 |
| EQ | **radio** | 原项目曲线，试听确认 |
| 变体数 | 1（`--variation_count 0/1`） | CrewChief 会在同文件夹内轮换变体，双变体可减少机械感，代价是时间翻倍 |

> 其余方案（macOS 原生 TTS、真人语音、其他 EQ 曲线）被否决的原因见[踩坑与经验总结 §1](踩坑与经验总结.md)。

### 2.2 音频格式（与 CrewChief 语音包一致）

**单声道 / 22050 Hz / 16-bit PCM**，峰值归一到 −1 dBFS，首尾静音已裁。

### 2.3 生成脚本的两个中文专属参数

两道防线都只对短句生效，长句不受影响：

| 参数 | 默认 | 作用 |
|---|---|---|
| `--artifact_trim_max_syllables` | 4 | 音节后若出现 ≥250ms 的近静音间隙，其后的内容判为幻觉音，裁掉 |
| `--attempts` / `--attempts_max_syllables` | 1 / 6 | 生成多个候选取最短的合格者。所有失败模式都让音频变长，所以最短的那个基本就是对的 |

数字包与短句用 `--attempts 5`，工程师那批大多是整句，稳定得多，默认 1 次即可。
为什么短句必须开多候选，见[踩坑与经验总结 §2.3](踩坑与经验总结.md)。

### 3.4 官方无台本的 29 个文件夹

CrewChief 自带的 `subtitles.csv` 覆盖不到 29 个文件夹 / **179 个 wav**，autovoicepack 那份旧
inventory 里同样没有。台本是**顺着 C# 里的 folder 常量读触发条件反推**出来的，不是翻译英文录音，
所以措辞不必照抄英文。结论钉在 `make_chief_inventory.py` 的 `MANUAL_TEXT` / `DROP` 两张表里：

| | 文件夹 | wav | 说明 |
|---|---:|---:|---|
| **手写中文** | 17 | 104 | `--manual` 单独导出，已是中文，**不要再送进翻译**，直接进 TTS |
| **不做** | 12 | 75 | 见下 |

不做的 12 个分三类：`acknowledge/breath_in` 是吸气声不是语音；`strength_of_field*` 属
`Ratings.cs`，AC 不加载；其余是 VSC、`virtual_energy`、`rejoining`、`wheel_damage`
——要么 AC 没有这功能，要么 `.cs` 里零引用是死音频。

⚠️ **两条手写台词是要和数字拼接的片段，中文语序不同，装包后必须实听验证**：

| 文件夹 | 拼接顺序 | 中文 |
|---|---|---|
| `lap_counter/race_starts_in` | 前缀 + 数字 + `timings/seconds` | 比赛开始还有 + 三十 + 秒 |
| `overtaking_aids/drs_activations_remaining` | 数字 + 后缀 | 三 + 次 DRS 可用 |

## 四、AC-only 带来的简化（已验证）

[CrewChief.cs:390-413](CrewChiefV4/CrewChief.cs:390) 按游戏裁剪事件模块，AC 会移除：

| 被移除的模块 | 收益 |
|---|---|
| **`PitManagerVoiceCmds`**（仅 RF2/LMU 加载） | ✅ **`SpokenNumberParser` 无需改造**。它按空格切词 + 硬编码英文数词，中文完全失效，但全项目仅 3 处调用且全在 PitManager。AC 不加载 → 省掉这处代码改动 |
| `IRacingBroadcastMessageEvent` | iRacing 专属指令不用翻译 |
| `Ratings`（iRacing/R3E 专属） | iRating / 安全等级相关不用翻译 |
| `CoDriver`（拉力专属） | 419 条路书文案不用做 |

⚠️ **注意**：语音指令的**语法本身基本不分游戏**——[SpeechRecogniser.cs](CrewChiefV4/SpeechRecogniser.cs) 里只有 6 处 `Game.XXX` 判断。所以「只做 AC」对指令翻译量减少有限，主要省的是代码改动和拉力部分。

### 5.1 autovoicepack 侧（✅ 已完成，改动只留在工作区，未提交）

| " | `YOUR_NAME` 占位符保护 + 丢失告警 | LLM 常把占位符一起翻译掉 |
| " | prompt 里带上消息类别（`lap_counter/green_green_green`） | 原本只喂一句孤立英文，`green, green, green` 译成颜色而不是绿灯 |
| " | 新增 `--glossary_file` | 赛车术语是机翻最稳定出错的地方，且**错得不随机**：`2 tenths` 每次都出「百分之二十」 |
| " | 新增 `--temperature`，默认 0.4 → **0.2** | 0.4 下同一句在两次运行里能给出「绿色」和「绿灯」两种结果 |
| " | prompt 加「按字面译，不要意译加词」 | 给了术语表后模型转向另一个极端，把 `green, green, green` 演绎成「起跑，起跑，起跑」 |
| " | `--ollama_host` / `--ollama_timeout`（默认 60s） | 原 host 写死、超时 20s 对大模型不够 |
| `Dockerfile` | 加装 `jieba` `pypinyin` | XTTS 的 `zh-cn` 分支依赖，实测确实缺失 |
| `pilot_mac.py`（新增） | 脱离 Docker/CUDA 的本地生成脚本 | Docker 镜像是 amd64+CUDA，Apple Silicon 跑不了 |

### 6.4 语料 CSV 格式

沿用 autovoicepack 的 inventory 格式，5 列，UTF-8：

```csv
audio_path,audio_filename,subtitle,text_for_tts,original_english
\voice\spotter\car_left,1.wav,左边有车,左边有车,car left
```

| 列 | 含义 |
|---|---|
| `audio_path` | 输出路径，**每一段都是 CrewChief 播报逻辑里的标识符** |
| `audio_filename` | 同一文件夹内的变体编号，CrewChief 轮换播放 |
| `subtitle` | 字幕文本，写入 `subtitles.csv`，覆盖层显示用 |
| `text_for_tts` | 送进 XTTS 的文本，通常与 `subtitle` 相同 |
| `original_english` | 英文原文，人工校对时对照用，不参与生成 |

⚠️ **文件夹名不能翻译。** `audio_path` 的每一段（`spotter/car_left`、`numbers/ten_thousand`）都要与英文包的目录结构**逐字对应**——那是播报逻辑里的标识符，不是描述性名字。写错了这条消息永远不会播，而且不报错。只有 `subtitle` 和 `text_for_tts` 是中文。

`YOUR_NAME` 是占位符，生成时被 `--your_name` 替换。翻译时不能连它一起译掉——LLM 经常这么干，`translate_phrases.py` 为此加了占位符保护与丢失告警（见 §5.1）。

## 八、语音指令（可后置）

**不需要录任何音频**——这是识别（输入），与播报完全解耦。但也不只是翻译：

| 层面 | 内容 | 量 |
|---|---|---|
| 翻译 | `speech_recognition_config.txt`：**423 个指令 key / 781 条短语** + 1099 个数字 key / 1498 条短语 | 数字部分高度规律，可脚本生成 |
| 引擎 | 装 `MSSpeech_SR_zh-CN_TELE.msi`（MS Speech Platform）或 Windows 中文语音识别包 | 找不到会弹窗报错 |
| 代码 | ✅ AC 无需改动（见 §4） | |

⚠️ **现实问题**：这套架构的语法是「短语列表精确匹配」（`GrammarBuilder` + `Choices`）。中文同音字极多（进站/近站、四/是），423 个指令 × 多个变体全塞进一个语法，误识别率会显著上升。

**建议只保留 30–50 个高频指令**，而不是全量翻译 781 条。配置文件注释本身也提到删减指令能大幅提升识别质量。

### 8.1 交付形态：一个覆盖文件，不用编译

`speech_recognition_config.txt` **没有** `{locale}` 按语言合并机制（UI 的 `ui_text/{locale}.txt` 有，
这个没有）。但有更合适的：

```
Documents\CrewChiefV4\speech_recognition_override.txt
```

这个文件存在时**整份替换、不做任何合并**——上游的设计意图就是让用户删掉用不上的指令。
正好是我们要的：原版程序可用、不用编译、程序更新不会覆盖。机制见
[踩坑与经验总结 §6.3](踩坑与经验总结.md)。

⚠️ 文件里**必须显式写 `language = zh` 和 `defaultLocale`**，缺失时代码会补成 `en` 和空串，
静默回到英文识别。

### 8.2 裁剪思路

423 个指令 key 里：

| 前缀 | 数量 | 处置 |
|---|---:|---|
| `RALLY_*` | 104 | **直接砍**，AC 不是拉力 |
| `PIT_*` | 61 | 保留高频几条 |
| `CHART_*` / overlay 控制 | 49 | 按需 |
| 其余状态查询、位置差距 | 209 | 主要挑选池 |

1099 个数字 key / 1498 条短语可脚本生成，但**建议大幅删减**——中文同音字在数字上最密集
（四/是、十/是、一/衣），全塞进一个 `Choices` 会显著拉低整体识别率。

## 十、环境搭建（M1 实测）

Docker 镜像基于 `nvidia/cuda` + amd64，Apple Silicon 无法使用。venv 建在 autovoicepack 目录下（本库不放二进制依赖）：

```bash
cd ~/Projects/crew-chief-autovoicepack
python3 -m venv .venv
.venv/bin/pip install coqui-tts
.venv/bin/pip install "transformers>=4.57,<5"
.venv/bin/pip install "torch<2.9" "torchaudio<2.9"
.venv/bin/pip install jieba pypinyin
```

**四个版本约束都是踩坑钉死的，别放宽**，逐条现象与原因见
[踩坑与经验总结 §7](踩坑与经验总结.md)。

生成速度（M1 / MPS）：短句 1.6–2.1 秒/条，长句 2.5–3.2 秒/条。

⚠️ XTTS v2 首次运行下载约 1.9GB 模型，需接受 **Coqui CPML 许可（非商用）**，`COQUI_TOS_AGREED=1` 可非交互接受。

### 翻译环境（ollama，第二阶段才需要）

XTTS 那套 venv 与 ollama 互不相干，装不装 ollama 不影响生成音频。

```bash
brew install ollama
brew services start ollama        # 或前台跑 ollama serve
ollama pull qwen2.5:14b           # 约 9GB
```

⚠️ 不要用 `qwen2.5:32b`，本机直接跑 ollama 必须显式传 `--ollama_host localhost:11434`，
原因同见[踩坑与经验总结 §7](踩坑与经验总结.md)。

### 11.1 UI 中文化（第三阶段）

```bash
# 看各波条数，顺便确认 913 条标识符被排除、划分覆盖全部待译条目

  --out translations/ui_wave1_zh.csv --glossary_file translations/glossary_ui_zh.txt

  --corrections translations/ui_wave1_corrections.csv \
  --out translations/ui_wave1_final.csv
```

#### 语料（`translations/`）

中间那份机翻输出**不能删**——LLM 输出不可复现，删了就没法重新应用修正表。
