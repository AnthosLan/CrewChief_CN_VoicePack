# Windows 验收清单（v1.0.0 Beta → 正式版）

> 这份清单是 **Beta 转正式版的唯一门槛**。制作侧的活全部做完了，剩下的都卡在同一件事上：
> **Mac 上编译不了 C#、跑不了 CrewChief、装不了中文语音识别引擎。**

## 为什么需要人工验收

所有产出都过了脚本体检——5308 条音频 `qa_pack.py` 异常 0 条，1305 条界面文案 `qa_uitext.py`
异常 0 条，54 个数字朗读用例全过。但这些检查有一条共同的天花板：

> **脚本能证明「格式对」，证明不了「说得通」。**

`qa_pack.py` 查的是时长、削波、字幕一致性，查不了「这句中文在这个场合说得通吗」。
`qa_uitext.py` 查的是折行、占位符、标识符，查不了「这个设置项名称看着像人话吗」。

所以 5308 条语音**没有任何人在比赛里听过**，1305 条界面文案**没有任何人在程序里看过**。
这是 Beta 状态最大的未验证面，也是最便宜的一项——跑几场 AC、翻几页设置就能覆盖大半。

## ① 语音听测（5308 条）

### 装法

按 [`packaging/INSTALL.txt`](../packaging/INSTALL.txt) 的「安装步骤」走完 1–8 步。要点：

- **整包替换**，不要装到 `Sounds\alt\`——用非默认工程师语音包时 CrewChief 会强制从基础包读
  `spotter*`，结果是工程师中文、spotter 永远英文
- 用原版程序的话，**合并前先删掉 `voice\numbers\`**，否则圈速会中英混播
- 属性页里设 `Override default Sound Pack location` 指向你复制出来的那份

### 怎么听

不用逐条听 5308 条。跑 2–3 场有对抗的比赛，重点听这五类高频播报：

| 分类 | 触发方式 | 听什么 |
|---|---|---|
| `spotter` | 有车贴近 | 左右内外说反没有；「安全」说得自然吗 |
| `flags` | 黄旗 / 蓝旗 | 旗语名称对不对 |
| `lap_times` | 每圈结束 | 圈速数字读法；「比最快慢零点几」 |
| `tyre_monitor` | 跑 10 圈以上 | 磨损/温度/抱死的说法 |
| `mandatory_pit_stops` | 带强制进站的比赛 | 进站窗口、限速、维修位 |

### 判据

- ❌ **反义**：让你做的和该做的相反（这是最危险的一类，波次 1 出现过 `safety car in` 进站译成「出现」）
- ❌ **同一术语两种说法**：同一场比赛里 `spotter` 一会儿叫观察员一会儿叫别的
- ❌ **听不清 / 截断 / 多出一段杂音**
- ⚠️ 机械感、语气平——已知问题，不算缺陷（XTTS 中文的固有脾气）

### 发现问题怎么办

记下**英文原文**（字幕覆盖层能看到），写进对应波次的
`translations/chief_wave<N>_corrections.csv`，格式 `英文原文,中文`（含逗号的英文要加引号）。
重新跑 `fix_translation.py` + `pilot_mac.py` 即可，只重生成改动的行。

⚠️ **单条重跑会毁掉整个文件夹的 `subtitles.csv`**，重跑后必须从最终 CSV 重建全部字幕文件。

## ② 界面文案（1305 条）

### 装法

把压缩包里的 `ui_text_zh.txt` 复制到：

```
%LOCALAPPDATA%\CrewChiefV4\
```

**改名为 `ui_text.txt`**，重启 CrewChief。

放这里而不是安装目录，是因为合并顺序里它优先级最高（`en.txt` → `ui_text\<语言>.txt` →
用户目录的 `ui_text.txt`），而且程序更新不会覆盖。

### 怎么看

1. 主界面：按钮、菜单栏、状态栏
2. 打开属性页（Properties），**逐个分类翻一遍**——这里占了 490 + 469 条
3. 鼠标悬停几个设置项，看 tooltip / help 文本

### 判据

- ❌ **看不懂在说什么**
- ❌ **设置项名称和它的帮助文本用词不一致**（帮助里提到的控件名和实际标签对不上）
- ❌ **句子中间缺字**——这正是 `NewlinesInLongString` 折行吞字的症状，理论上已经修掉，
  但这是唯一能真正确认的场合
- ⚠️ 有一类设置项**故意保持英文**：值是 `UI_STARTUP_AND_PATHS`、`RESTART_REQUIRED` 这种
  全大写标识符的，那是程序内部用的，译了会让设置项从分组里消失。**不是漏做**

### 发现问题怎么办

记下**英文原文**，写进对应波次的 `translations/ui_wave<N>_corrections.csv`，
重跑 `fix_uitext.py` + `make_uitext_inventory.py --to_txt`。

## ③ 中文控件宽度

和②同时做，不用单独跑一遍。

WinForms 的控件宽度是写死的，按英文文本长度设计的。中文通常**比英文短**（同样的意思字数更少），
所以多半没事，但需要确认：

- 属性页左侧的设置项名称有没有被截断成 `启用刹车损伤播...`
- 按钮上的文字有没有超出边框
- 下拉框里的选项显示完整吗

发现截断就把那条译文改短，同样走 `ui_wave<N>_corrections.csv`。

## ④ C# 单元测试（34 条）

> **这 34 条测试从写出来到现在一次都没真跑过。** `NumberReaderZh` 的正确性目前只有
> `make_numbers_inventory.py --verify` 那份 Python 镜像背书——两边是照着同一套规则各写一遍，
> 镜像通过不代表 C# 编译得过、跑得对。

### 步骤

1. 把 `src/NumberReaderZh.cs` 拷进 `CrewChiefV4/`
2. 应用 `patches/crewchief-zh-numberreader.diff`
3. **用 Debug 配置构建**（Release 构建不含单元测试）
4. 跑：

```bash
vstest.console.exe UnitTest\bin\Debug\UnitTest.dll /TestCaseFilter:"FullyQualifiedName~TestChinese"
```

### 判据

34 条全过。任何一条失败都要对照
[数字与时间朗读设计](数字与时间朗读设计.md) 看是 C# 写错了还是 Python 镜像写错了，
**两边必须同时改**——Mac 上编译不了 C#，`--verify` 是唯一能发现两边跑偏的手段。

## ⑤ 时间播报语序

### 背景

`CommonActions.reportCurrentTime()` 原本按 `hour + oh + minute + am/pm` 拼片段，是英文语序。
我们已经发布了 `alarm_clock/am`=上午、`pm`=下午，所以**不打补丁的话中文包会念成「八 零 五 上午」**。

补丁加了 `NumberReaderZh.GetTimeOfDaySounds()`，输出「上午八点零五分」。
拼装规则放在 `NumberReaderZh` 是为了共用量词规则——**2 点要读「两点」不是「二点」**。

### 步骤

1. 应用同一个补丁，**Release | x86** 构建
2. 启动后日志里应该出现 `Using NumberReaderZh for soundPackLanguage zh`
3. 语音指令说「现在几点」，或用绑定的按键触发

### 判据

| 时刻 | 应该听到 |
|---|---|
| 08:05 | 上午八点零五分 |
| 08:00 | 上午八点 |
| 14:05 | 下午**两**点零五分 |
| 12:00 | 下午十二点 |
| 00:00 | 上午十二点 |

❌ 听到「八 零 五 上午」说明补丁没生效。
❌ 听到「下午**二**点」说明 `countWithUnit` 的量词分支没走到。

另外 `ColloquialTime` 也加了中文表（把 `colloquial_time` 设置打开才走那条路），
它走**系统 TTS** 不是语音包，需要 Windows 装了中文 SAPI 语音才有意义。没装就别开这个开关。

## ⑥ 中文语音指令（45 条）

### 装法

1. 装识别引擎，二选一：
   - `MSSpeech_SR_zh-CN_TELE.msi`（Microsoft Speech Platform 11）
   - Windows 设置 → 时间和语言 → 语言 → 添加中文，勾选「语音识别」
2. 把 `speech_recognition_override.txt` 复制到 `我的文档\CrewChiefV4\`
3. 重启 CrewChief

这个文件会**整份替换**默认配置，没列出来的指令不再监听——这是上游的设计意图（让用户删减指令），
不是缺陷。

### 怎么测

按住语音键（或用触发词），依次说：

```
车损报告      车辆状态      赛况          胎温多少      胎压多少
我第几        前面差多少    后面差多少    谁在领跑
我的最快圈速  还有多少油    油耗多少
再说一遍      能听到吗      安静
```

### 判据

- ✅ **识别率 > 80%** 算可用
- ❌ 某条指令**总是**识别成另一条——把那条从文件里删掉，或换个说法
- ❌ 整体识别率很低——先确认引擎装对了（日志里会打印 `Got SRE for zh-CN`）

⚠️ 中文同音字多，这是**唯一必须实测的一项**——45 条已经是砍过的（全量是 423 条），
但砍到什么程度合适只有听了才知道。

发现某条不好用就直接编辑 `src/speech_recognition_override.txt`，一行一条，改完重启即可。

## ⑦ 字幕覆盖层中文

### 步骤

1. 属性页里打开字幕覆盖层
2. 进游戏，看有播报时字幕显示的是中文还是方块

### 如果是方块

覆盖层默认字体是 `Microsoft Sans Serif`，没有中文字形。改：

```
我的文档\CrewChiefV4\subtitle_overlay.json
```

找到 `"fontName"` 那一行，改成有中文字形的字体：

```json
"fontName": "Microsoft YaHei",
```

工程师覆盖层是同一套设置，文件叫 `crewchief_overlay.json`，同样改法。

**两个 json 都是首次运行时自动生成的，找不到就先启动一次。改完重启生效，不用重新编译。**

### 判据

字幕能正常显示中文。这一项的改法早就定了，只差确认默认字体够不够用——
如果 Windows 的默认字体已经能显示中文，那 INSTALL.txt 里那一节就可以简化。
