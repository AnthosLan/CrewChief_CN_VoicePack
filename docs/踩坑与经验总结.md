# 踩坑与经验总结

> 本文收录实测结论、失败教训、注意事项与风险登记——**「为什么这么做」和「哪里会翻车」**。
> 流程、参数与命令见[制作方案](中文语音包制作方案.md)；许可见[许可与分发](许可与分发.md)。

大部分条目的代价是真实的机器时间或返工，写下来是为了不再付第二次。

---

## 一、被否决的方案

| 方案 | 结果 | 原因 |
|---|---|---|
| macOS 原生中文 TTS 做 baseline | ❌ 更差 | 共振峰合成的机械感被一起克隆进去；`收到` 出现 576ms/音节 的拖音异常 |
| CrewChief 自带真人语音做 baseline | ❌ 放弃 | 效果不佳，且涉及署名个人（Geoffrey Lessel、Matt Orr 等）的声纹 |
| warm / full / broadcast EQ | ❌ 未采用 | 试听后选定 radio |
| baseline 从 14 秒扩到 39 秒 | ⚠️ 收益有限 | 音高标准差仅从 37.0Hz 降到 32.7Hz（−12%），XTTS conditioning 在 15 秒左右接近饱和。但成本已付，保留 |

## 二、XTTS 中文的固有脾气

### 2.1 中文 TTS 念拉丁字母不可靠

同一个根因在五个地方连续撞到，**是稳定行为不是随机抖动**，`--attempts 8` 重跑无效：

| 现象 | 实测 |
|---|---|
| `bar` / `PSI` 被 QA 判异常 | 单音节拉丁词时长落在中文阈值外 |
| `GTC` 三个字母 | **1.73 秒**，重跑无效，稳定复现 |
| `DTM赛车` | 截断到 **0.21 秒**（光两个汉字也要 0.34 秒） |
| `DRS 不再可用` | **0.49 秒**，比四个汉字单独念还短 |
| `DRS` 在句中 | 只占 **0.25 秒**，三个字母名至少要 0.5 秒 |

由此定下判断标准：**主体是英文缩写或专有编号的播报，整个文件夹不做，回落英文原音。**

语音包覆盖在英文包副本上，**不发的文件夹自动播原来的英文**，所以「不做」是可用选项而不是缺失。
据此排除 **60 个文件夹 / 202 条音频**：车辆组别号（GT3/GT300/LMP2/DTM/Carrera Cup）、组别编号
（Group A/C/5）、`overtaking_aids` 整个分类（DRS/KERS/push-to-pass）。加上原有的车手名和弯角名，
完整清单见[制作方案 §3.2](中文语音包制作方案.md)。

排除规则在 `make_chief_inventory.py` 的 `SKIP_EXACT` 与 `DROP_CLASS_PATTERN`，重新切语料自动生效。

### 2.2 拉丁字母与汉字之间不能留空格

XTTS 会在空格处断句并吞掉后半段：`DRS 不再可用` 只有 0.49 秒，`GT4 车` 截断到 0.22 秒。
`fix_translation.py` 的 `TERM_FIXES` 里有一条全局去空格规则兜底。

### 2.3 短句必须开多候选

一两个汉字是 XTTS 最不稳的地方——会在音节前后补一段幻觉音，或者干脆把音节念两遍。

波次 1 的 1921 条用默认 `--attempts 1` 生成，`qa_pack.py` 报出 **9 条异常**，全是 2–5 音节的短句：
6 条过短（最极端的 `你进来了` 只有 0.13 秒 / 4 音节 = 33 ms）、3 条过长。

根因是 `pick_best_candidate` 有 `--min_ms_per_syllable`（默认 90）这道闸，但**只有一个候选时它没得选**，
只能把不合格的返回。对这 9 条按下面的参数重跑后异常清零，语速范围从 33–548 ms/音节收敛到 93–419，
整批只花 66 秒：

```bash
--attempts 5 --attempts_max_syllables 0
```

**更省事的做法是一开始就对短句开多候选，而不是事后补。**

⚠️ **重跑之后必须重建 `subtitles.csv`**——`pilot_mac.py` 按本次跑过的行重写字幕文件，单条重跑会让那个
文件夹只剩 1 行字幕，其余条目在覆盖层上什么都不显示，而音频本身是好的、听不出问题。原因见
[CLAUDE.md](../CLAUDE.md) 里那条约束。

## 三、机器翻译错在哪

**机翻结果不能直接进 TTS。** 通读和脚本扫描各能发现一半，两种都要做。

### 3.1 波次 1：1452 条改了 404 条

错误不是随机分布的，按危险程度排：

| 类型 | 例 | 后果 |
|---|---|---|
| **反义** | `safety car in`（进站）→「出现」；`gone off`（冲出赛道）→「脱困」；`reeling you in`（追近）→「套你圈」 | 车手照做就是反向操作 |
| **同一术语多种译法** | `spotter` 在 acknowledge 一个分类里出现 8 种译法，含「报站」（公交车报站名）、「领航员」（那是拉力 codriver） | 听起来像换了个人在说话 |
| **量纲错** | `2 tenths`（零点二秒）→「百分之二十」 | 数值完全错 |
| **片段直译** | `laps ahead` →「圈数领先」，中文量词必须跟在数字后面才拼得出「你三圈领先」 | 拼出来不成句 |
| **书面语** | `go, go, go` →「去，去，去」 | 喊不出口 |

前三类靠通读发现，后两类靠脚本扫描（残留数字、省略号、悬空逗号、繁体字、中文夹空格）。
**两种都要做，各自会漏掉对方那一半。**

### 3.2 波次 2：新增三类（1173 条改了 212 条）

前一波已知的错照旧，另外新增：

| 类型 | 例 | 为什么难发现 |
|---|---|---|
| **单位当成别的东西** | `bar`（压力单位巴）→「轮胎监测」；`psi` →「胎压」 | 译文本身像个正经术语 |
| **原文 typo 被顺着译** | `get some head into these brakes`（head 是 heat 笔误）→「给刹车**降温**」 | 意思正好反了 |
| **同义词全译成一个词** | hypersoft / ultrasoft / supersoft 三种配方都叫「超软胎」 | 单看每条都对 |

还有一条 `cooking`（过热）被系统性译成「磨损」共 14 条，「你的左前胎在磨损」读起来完全通顺——
**译文越通顺越难发现，只能对着原文逐条读。**

### 3.3 波次 3+4：组别名不能翻译

GT3、GTE、Group C、LMP2、DTM 这些是专有名词，中文车手也说原名。机翻的处理五花八门：
`GTC` 和 `GTE` 都译成「GT」——**尾字母丢失，两个不同组别变成同一个**；`Group 6` 译成「组别」，
数字没了。共 61 条改回原文。

### 3.4 术语表要在开跑前配齐

波次 2 第一次跑到 294 条时发现，它的高频词几乎全不在术语表里——`penalty` 117 处、`track limits` 98 处、
`stop-go` 41 处、`serve` 33 处、`locking` 28 处，加起来 300 多处靠模型自由发挥。**停掉重跑**，术语表从
45 条扩到 82 条。代价 85 分钟机器时间，换来的一致率：

| 术语 | 一致率 |
|---|---|
| `track limits` → 赛道界限 | 65/66 |
| `wear` → 磨损 | 29/29 |
| `pressures` → 胎压 | 20/20 |
| `locking` → 抱死 | 25/28 |

对照波次 1 的 `spotter` 出现 8 种译法，这次没有同类问题。**开跑前先扫一遍语料的高频术语**，
比事后写几百条修正划算得多。

⚠️ **术语表按无线电口语选词，不是按词典。** 一开始写 `aero = 空气动力套件`，结果满屏「一些轻微的
空气动力套件损坏」——工程师不会这么喊。改成「空力」。

### 3.5 修正表要跨波次继承

波次 2 定的「空力」「标准胎」口径到了波次 3 全丢了，`aero` 又变回「空气动力套件」。
`fix_translation.py` 的 `--corrections` 接受多个文件，后面的覆盖前面的，**把前几波的修正表一起传进去**：

```bash
--corrections chief_wave1_corrections.csv chief_wave2_corrections.csv chief_wave34_corrections.csv
```

只对最后一个（本波）文件报「未命中」——继承来的条目匹配不上是正常的，全报出来会淹没真正要看的。

修正表**按 `original_english` 索引**，所以换 prompt 重新翻译后照样生效。

⚠️ **修正表里含逗号的英文必须加引号。** 不加的话 CSV 会把它拆成三个字段，第二个字段（英文的后半截）
被当成中文译文写进语音包。`fix_translation.py` 有字段数校验会直接报错退出，别绕过它。

## 四、脚本自身踩过的坑

### 4.1 数字归一化正则把 `GT300` 变成「GT3零」

**不是模型错译，是 `normalise_numerals` 的正则**：`(?<![A-Za-z])(\d{1,2})` 在 `GT300` 里匹配到末尾的
`00` 并转成「零」。在修正表里写 `GT300,GT300` 也没用——**归一化跑在人工修正之后**，三层顺序不能换。

正则已改成 `(?<![A-Za-z\d])`，同时排除字母和数字前缀。这类 bug 只在「字母+3 位数字」上触发，
前两波的语料里恰好没有这种模式，**换一批语料才暴露**。

### 4.2 `qa_pack.py` 的音节计数改了三版

原来只数汉字，把拉丁字母当 0 音节，含 DRS/KERS 的条目全部虚报「过长」。改成逐字母计数后又矫枉过正，
把 `别忘了用KERS` 报成「过短」。靠对照实验定的案：

| 文本 | 时长 |
|---|---:|
| `别忘了用` | 0.55s |
| `别忘了用KERS` | 0.85s |
| `别忘了用凯尔斯` | 1.03s |

KERS 确实发音了（多 0.30 秒），但 XTTS 把它当**一个词**而不是逐字母拼读。最终规则：单个字母算
1 音节，缩略词整体算 2 音节。

### 4.3 音频链里重采样必须在归一化之前

带限插值会在瞬态上过冲，反过来会让 16-bit 写入削波。这是修过的 bug（`pilot_mac.py:302`），
`qa_pack.py` 的削波检查就是它的回归防线。

## 五、装包陷阱

### 5.1 ⚠️ 不要装到 `alt/` 目录

CrewChief 在使用非默认工程师语音包时，会**强制**从基础包读取 `spotter*` 和 `radio_check*`
（[Sounds.cs:1147-1162](CrewChiefV4/Audio/Sounds.cs:1147)）：

```
选了 alt 语音包 + 公路赛：
  spotter* / radio_check*  →  强制从【基础包】读（英文）
  其余所有 voice 文件夹     →  从 alt 包读
```

按 autovoicepack README 的装法（拷到 `Sounds\alt\`），结果是**工程师说中文、spotter 永远说英文**——
而 spotter 恰恰是比赛中出现频率最高的播报。正确装法见[制作方案 §7](中文语音包制作方案.md)。

### 5.2 防覆盖的实际机制

CrewChief 不会静默覆盖，它只把语音包下载按钮点亮，用户点了才下载。按钮亮不亮看
`latest > current`（[SoundPacks.cs:117](CrewChiefV4/UserInterface/SoundPacks.cs:117)），`current` 取自语音包根目录的
`sound_pack_version_info.txt`，`latest` 按**语言**从上游 XML 取：

| 语言标记 | 取到什么 | 结果 |
|---|---|---|
| `zh`（打了补丁的构建） | 上游 XML 没有 zh 段，`voiceMessageUpdatePacks` 为空 | 按钮永远灰，天然免疫 |
| 空（原版程序） | [MainWindow.cs:607](CrewChiefV4/UserInterface/MainWindow.cs:607) 的 `soundPackLanguage == null ? "en"` 回落到 en，拿到真实英文版本号 | 上游一发新版按钮就绿，需要把 `current` 撑大 |

⚠️ `-skip_updates` **不能**当防线。它只跳过 `AutoUpdater.Start()`（程序本体更新），语音包的
XML 照样下载解析（[MainWindow.cs:598-608](CrewChiefV4/UserInterface/MainWindow.cs:598)）。

## 六、环境依赖的四个坑

按踩到的顺序，四个版本约束都是钉死的，别放宽：

| 现象 | 原因 | 解法 |
|---|---|---|
| `No module named 'torch'` | coqui-tts 0.27 不再声明 torch 依赖（让用户自选 CUDA/CPU 版本） | 单独装 |
| `cannot import name 'isin_mps_friendly'` | transformers 5.x 移除了该函数 | 降到 4.57.x |
| `torchcodec library is required` | torch 2.9+ 强制要 torchcodec，而它又要系统装 ffmpeg | 降到 torch 2.8 规避 |
| XTTS 中文分支报错 | 缺中文 g2p 依赖 | 装 `jieba` `pypinyin` |

另外两条：

- ⚠️ **不要用 `qwen2.5:32b`**：19GB 模型在 16GB 内存的 M1 上会疯狂 swap。用 `qwen2.5:14b`（约 9GB）或云端 API。
- `translate_phrases.py` 的 `--ollama_host` 默认是 `host.docker.internal:11434`（给 Docker 用的），
  本机直接跑必须显式传 `localhost:11434`，否则连不上。
- ⚠️ 翻译输出 CSV 若已存在会被当成断点续跑、用它预热缓存，**改了 prompt 或术语表后必须先删掉**。

## 七、风险与未决项

| 风险 | 影响 | 应对 |
|---|---|---|
| **XTTS 中文音色带英文口音** | 听感 | 已知问题，Bart 音色可接受。彻底解决需真人中文录音做 baseline |
| **数字/时间拼接韵律** | 圈速、差距播报听起来生硬 | `NumberReaderZh` 必须先设计定稿再生成音频 |
| **短句不稳定** | 2–4 音节的 `安全`、`还在` 等 | 见 §2.3，用 `--attempts` 多候选 |
| **单变体机械感** | 同一句反复听会腻 | 原包每文件夹 2–7 个变体轮换，中文包可用 `--variation_count 1` 做双变体 |
| **XTTS 非商用许可** | 音频不能商用、不能改成 MIT | 见[许可与分发](许可与分发.md) |
| **baseline 音色的来源条款** | 比 CPML 更容易被忽略 | Bart 是 ElevenLabs 合成音，同见[许可与分发](许可与分发.md) |
| 中文语音识别率 | 语音指令可用性 | 砍到 30–50 个高频指令 |
